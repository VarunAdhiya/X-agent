## Enforced application limits

- `PUBLISHING_ENABLED=false`, `X_COST_APPROVED=false` and database `publishing_enabled=false` are independent defaults. Live X also needs all four OAuth credentials and `DRY_RUN=false`.
- `GEMINI_FREE_TIER_CONFIRMED=false` blocks calls until the operator checks a genuinely free project/model. This flag cannot inspect Google's billing account; a mistaken confirmation cannot prevent provider billing. Keep billing unattached.
- No app daily Gemini request cap. Usage is tracked; a minimum 15-second separation remains. Google free-tier quotas still apply. No billing upgrade or paid fallback is enabled.
- Ordinary daily operation uses one generation request, with no paid search grounding. Regeneration consumes more requests. Invalid output is rejected rather than automatically consuming a retry loop.
- Discovery fetches up to 12 HN items, four RSS feeds and at most 16 shortlisted articles/prompts. Requests and body sizes are bounded. Stored excerpts are capped at 6,000 characters. Polling reads only the small settings row, not all source content.
- Retention removes delivered outbox entries after 30 days, processed Telegram inbox payloads after seven days, logs after 90 days, and unused topics after 30 days. Published drafts and revision history remain; monitor storage over time.
- Image tags and npm packages are pinned. Upgrades require a reviewed version change; no automatic updater is installed.
- GitHub Actions is optional. Public repositories normally have free standard runners; for a private repository inspect included minutes and disable Actions if any charge is unacceptable. Local `npm run verify` is sufficient.

Cloud infrastructure cannot offer a production SLA at zero cost. Capacity shortages, free-tier pauses, quotas and VM reclamation can interrupt daily generation. The application fails closed: it never fills a missing slot with fabricated or unapproved content.
